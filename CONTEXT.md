# TMB

Глоссарий Tool Mediation Broker: словарь посредничества между агентом и привилегированным выполнением команд. Здесь зафиксированы договорённости о смысле слов, а не факты об уже написанном коде; деталей реализации нет.

## Language

**TMB (Tool Mediation Broker)**:
Брокер между агентом (opencode) и привилегированным выполнением команд: агент просит, человек одобряет касанием Touch ID, команда выполняется. Неофициальная расшифровка: «trust me brother».

**Запрошенная команда**:
Явно заданная программа плюс упорядоченный массив аргументов. Выполняется ровно она, без неявного shell; явно указанный интерпретатор считается обычной запрошенной командой со своим argv.
_Avoid_: командная строка, shell-строка

**Подписанное разрешение**:
Авторизация ровно одной запрошенной команды для конкретного принимающего хоста и пользователя выполнения. У разрешения есть уникальный идентификатор запроса, время выдачи и короткий срок годности. Действует оно максимум на одну попытку запуска и не гарантирует завершения команды.
_Avoid_: сертификат, force-command, пропуск

**Одобрение**:
Человек видит у доверенного подписанта точный запрос: хост, пользователь выполнения, абсолютный путь к исполняемому файлу, упорядоченный argv. Подтверждение только касанием Touch ID. Нет одобрения, нет разрешения.
_Avoid_: считать ask-диалог агента гарантией безопасности

**Доверенный подписант**:
Доверенная сторона, которая показывает человеку точный запрос и после касания Touch ID выпускает подписанное разрешение. Для первой версии подписант находится на Mac; его бэкенд пока не выбран.
_Avoid_: считать подписантом агента

**Погашение разрешения**:
Переход подписанного разрешения в использованное состояние до запуска команды. Погашение однократно, нераздельно (атомарно) и переживает перезапуск компонента; повторное предъявление, гонки и переигровка отклоняются.
_Avoid_: считать погашение обратимым или гарантией завершения команды

**Приёмный шлюз**:
Логическая проверка авторизации на принимающем хосте, встроенная в sudo. Это не отдельный самостоятельный процесс, порождающий программу: шлюз проверяет подписанное разрешение и погашает его до запуска, а одобренные программа и argv передаются фактическому выполнению sudo без изменений, двойного выполнения нет. По пути TMB запуск без проверки разрешения шлюзом недопустим; обычный парольный sudo остаётся отдельным путём.

**Обычный sudo**:
Привычный парольный путь: sudo спрашивает пароль человека. Отдельная дорожка, TMB её не заменяет и не меняет.

**Журнал**:
История подписанных команд для подписанта: кто, что, когда, на каком хосте, чем закончилось. Не шлюз, а летопись.
