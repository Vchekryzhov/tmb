# ADR 0003: Транспорт песочницы, TCP endpoint (вариант B) с mTLS-идентичностью

Дата: 2026-10-09. Расширяет [ADR 0002](0002-standalone-tmb-broker.md): закрывает открытый в нём вопрос sandbox-слоя и транспорта.

## Контекст

ADR 0002 оставил слой песочницы вопросом MVP. Исследование OpenShell (RESEARCH-OPENSHELL.md) рекомендовало вариант B: единственный TCP endpoint, разрешённый одним правилом `network_policies`. Вариант A (bind-mount unix-сокета) остался запасным, но он ослабляет admission песочницы (`enable_bind_mounts`), канал не медируется OpenShell вовсе, и socket-bind-mount не верифицирован в доках. PoC брокера живёт на unix-сокете с SO_PEERCRED, который на TCP не существует. ADR 0002 прямо требует аутентификацию beyond SO_PEERCRED как обязательную работу MVP.

Факты, закрывшие выбор (документация NVIDIA/OpenShell @ v0.1.x, коммит fe2dd3e):

- `protocol: tcp` это первоклассный тип сетевого правила (байтовый passthrough без инспекции, документированный пример: базы данных);
- `tls: skip` это документированный режим ровно для клиентских сертификатов («when the client must complete TLS itself, for example to present a client certificate»);
- супервизор сам открывает внешнее соединение, поэтому получатель видит адрес супервизора, а не песочницы: IP-идентичность невозможна на обоих концах.

## Решение

OpenShell изолирует агента и контролирует соединение tmb-клиента с брокером; TMB проверяет запрос, получает одобрение человека и выполняет команду на принимающем хосте. OpenCode используется в базовом образе проверочного стенда, но контракт TMB не зависит от конкретного агента.

- Вариант B: брокер слушает TCP endpoint; в политике песочницы он разрешён ровно одним правилом `network_policies` c `protocol: tcp` и `tls: skip`. В проверочном стенде майлстоуна #5 весь остальной egress закрыт deny-by-default; LLM API и другие внешние сервисы в этом стенде не подключаются.
- Существующий протокол не меняется: length-prefixed JSON (4-байтовый big-endian заголовок) поверх TCP; framing транспортно-агностичен, go.mod остаётся без внешних зависимостей.
- Идентичность запросчика: mTLS. Клиентский сертификат на песочницу; allowlist брокера хранит SHA-256 fingerprint'ы разрешённых сертификатов; fingerprint заменяет uid из SO_PEERCRED в журнале, claim-метаданных и на approval-консоли («requester: cert fp=…»). Идентичность только сертификатная: IP не используется.
- Привязка одобрения к идентичности: pending-одобрение хранит идентичность запросчика (uid | cert fp); `claim` с другой идентичностью отклоняется кодом `requester_mismatch` до любого погашения токена, и одобрение остаётся выкупным для исходного запросчика (N10 на unix-пути, O9 на сертификатном).
- Аутентификация брокера (взаимный mTLS): клиент проверяет цепочку серверного сертификата против CA из `TMB_CA` и имя точки входа; ServerName берётся из хост-части `TMB_ADDR`; `InsecureSkipVerify` запрещён и в коде отсутствует. Чужой CA или чужой SAN даёт транспортный отказ (exit 3) до отправки какого-либо кадра.
- Unix-сокет остаётся вторым листенером: host-local путь с SO_PEERCRED (N-серия проверочного реестра жива нетронутой). В коде вводится одна абстракция «идентичность запросчика» (uid | cert fp), выбираемая per-listener.
- Аудит TMB-канала живёт в TMB: `tls: skip` делает канал непрозрачным для OpenShell, JSONL-журнал брокера служит летописью канала (как зафиксировано в RESEARCH-OPENSHELL Q5).
- Клиент в песочнице: статический Go-бинарник, запечённый в кастомный образ поверх пиненного opencode-образа; адрес `TMB_ADDR=host.openshell.internal:<port>` передаётся через `--env` при create.
- Топология доказательства: macOS + Docker Desktop (gateway как нативный бинарник, супервизор как отдельный контейнер; пререквизиты: host networking включён, Enhanced Container Isolation выключен). Одобрение через консоль foreground-брокера, как в PoC.
- Вне скоупа этого решения: MCP-over-HTTP и HTTP/JSON (будущий этап, кандидат на #2/#3), env/cwd-политика, TOCTOU-харденинг, packaging, аудит-пайплайн.

## Статус

Принято (2026-10-09) по итогам грила: скоуп майлстоуна #5 включает OpenShell-обвязку и минимум аутентификации, выделенные из issue #4.

## Последствия

Положительные:

- Канал песочница→брокер медируется и логируется OpenShell на уровне соединения без ослабления admission песочницы.
- TCP-endpoint добавляется в живую песочницу без пересоздания, что упрощает проверку O2 (изъятие правила → deny).
- Kernel-auth (SO_PEERCRED) сохранён для host-local пути; сертификатная идентичность закрывает allowlist, журнал и approval-дисплей одной конструкцией.
- Одобрение живёт и погашается в рамках одной идентичности: перекрёстный claim чужого одобрения отклоняется до погашения, повторное предъявление исходным запросчиком остаётся возможным.
- Подмена брокера на пути обнаруживается самим клиентом (верификация цепочки + ServerName): чужой endpoint не получает ни запроса, ни одобрения.

Отрицательные и риски:

- CA-инфраструктура появляется в харнессе (генерация CA и клиентских сертификатов на прогонах).
- Канал непрозрачен для OpenShell (`tls: skip`): инспекция уровня запросов невозможна, это осознанный размен.
- OpenShell 0.1.x API churn: версии пинуются; в реализации майлстоуна закреплена 0.1.3 (первоначальная 0.1.2 заменена примечаниями к #5).
- Консольный manual-approval сериализован мьютексом на все соединения; при нескольких TCP-клиентах станет узким местом (перенос в packaging-этап).
- «Хост» доказательства это Docker Desktop VM, не настоящий хост; вердикт обязан это фиксировать.
