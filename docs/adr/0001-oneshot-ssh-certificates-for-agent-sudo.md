# ADR-0001: Одноразовые SSH-сертификаты (force-command) для привилегированных команд агентов

Дата: 2026-10-04
Статус: принято

## Контекст

Агенты opencode выполняют команды в неинтерактивном bash (stdin отключён), поэтому sudo с паролем невозможно: команда падает с «a terminal is required to read the password». Нужен способ давать агентам привилегии только с явного биометрического участия человека (Touch ID на MacBook), на трёх поверхностях: локальный Mac, omen_local (Ubuntu), nas (Synology DSM 7). Требования: показ полной команды до выполнения; одно касание на команду; без паролей в чате; настройка хостов без хардкода.

## Решение

- **Локальный Mac**: `/etc/pam.d/sudo_local` с `pam_tid.so` (переживает обновления macOS) + `Defaults timestamp_timeout=0` — касание на каждую sudo-команду, без кэша. Показ команды — ask-диалог opencode.
- **Удалённые хосты**: короткоживущий SSH-сертификат (TTL ~60 секунд) с force-command, вшитой в сертификат, и principal=root. CA-ключ — в Secure Enclave Mac (Secretive); `ssh-keygen -U` подписывает сертификат через агент → Touch ID на каждую подпись. На хостах: `TrustedUserCAKeys` + `PermitRootLogin forced-commands-only`. sudo на хостах не используется вовсе.
- **Оболочка `tmb <host> <command...>`** — единая точка: показ команды, подпись, выполнение, запись в журнал.

## Альтернативы

1. **sudoers NOPASSWD-allowlist + Secretive для SSH-аутентификации**: allowlist живёт на каждом хосте, каждая правка требует root-доступа туда; полномочия не истекают. Отвергнуто: пользователь хочет «подписал — выполнилось один раз», состояние на хостах — статический минимум.
2. **Teleport / HashiCorp Vault / step-ca**: полноценный PAM с approvals и аудитом; отдельный сервер и обслуживание. Отвергнуто как танк для двух домашних хостов.
3. **touchid-remote (PAM-модуль на Linux + обратный туннель)**: не работает на DSM, больше движущихся частей.
4. **Свой подписывающий демон с Touch ID**: не нужен, если `ssh-keygen -U` работает с агентом Secretive (проверить при установке; fallback — CA-ключ на диске + biometric-обёртка вокруг ssh-keygen).

## Последствия

- Разовая правка `sshd_config` на хостах; на DSM она затирается обновлениями — восстанавливается Task Scheduler (boot, root).
- Риск запереть SSH при кривой правке sshd_config — митигируется открытой сессией при установке.
- force-command — точная строка: вариации аргументов = отдельные записи (в будущем — host-side allowlist, отложено).
- Человек и есть политика: что подпишет, то и выполнится. Журнал — единственная летопись.
